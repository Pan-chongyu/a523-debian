# 实时开机日志与连续显示

[English](../BOOT-CONSOLE.md) · [日本語](../ja/BOOT-CONSOLE.md) · [Español](../es/BOOT-CONSOLE.md)

原机已实现从 SRAM 引导显示连续交接给 Linux：星空猫图片之后显示**真实内核启动日志，再进入默认向右横屏的 XFCE 桌面**。用户确认“显示日志了，没有彩屏黑屏也没了，桌面触摸正常”。

原流程会先关闭 PWM、DSI 和面板电源，再启动原生驱动；电源域驱动注册时还可能关闭尚未有 Linux 消费者的显示域。新流程先核对 SRAM 回执、实际时序、扫描地址和供电，保留已开启的 VO0、VO1、DE 三个域。原生驱动接管时钟和 GPIO，不复位面板、不切断供电或背光，将可见日志复制到 DMA32 双缓冲后提交正常扫描。冷初始化路径在首帧确认前保持黑色遮罩，移除原来的彩条和四色测试缓冲。

ARM64 文字渲染器读取 `/dev/kmsg`，将真实记录按向右横屏写入保留帧缓冲；原生模块接管后停止写旧物理缓冲，继续向 VT1 输出，随后进入桌面。它不显示模拟进度。最早的 SRAM 图片保持原样；实时日志要等 Linux 用户空间能够读取内核记录，本轮没有宣称按下电源就立即显示日志或进一步提前首次亮屏。

两次正常启动记录了 422 / 424 条内核消息，均成功接管原生显示。第二次日志首帧由服务在 **Linux 启动后 5.48 秒**确认，五个桌面进程全部创建时间为 **20.69 秒**；这些不是按键秒表时间或目视桌面就绪时间。两轮 42.51 / 44.06 秒联合负载覆盖 CPU、2.5 GiB 内存、GPU 图形和计算、600 帧硬解及直接文件写读；五轮真正面板休眠唤醒核对了 DSI、DCS 状态位和背光。显示、MMC、IOMMU 错误均为零，没有失败服务。[完整实测 JSON](../../reports/boot-console-20261114.json)。

CPU 保持 performance 1416/1800 MHz，GPU 最低请求 600 MHz 且保留温控与故障上限，HS200 为 100 MHz，zram 为 2 GiB，不预加载浏览器。引导器、图片资产、压缩引导包、两份 GPT 和后备槽实读未变。父层原始字节及安装文件校验保留；日志会改变保留帧缓冲，且 DE 故意持续运行，因此本子层使用独立验证器，不改写历史父层认证。

使用准备好的准确目标内核源码和构建配置，可构建公开源码：

```sh
sh research/tools/build_boot_console.sh KERNEL_SOURCE KERNEL_BUILD OUTPUT_DIRECTORY
```

该入口已实际构建，两份模块、文字渲染器、内核字体与已安装版本 SHA-256 一致。显示源码在 [`research/firmware/screen-boot-console`](../../research/firmware/screen-boot-console)，电源域、交接脚本和日志程序在其上一级目录。字体从内核 GPL 许可的 `lib/fonts/font_8x16.c` 提取。构建命令不安装文件；原机验证脚本依赖准确父层及受保护安装器，属于研究记录，不能作为通用更新命令。未公开身份快照、凭据或私钥。

三个显示域保持供电，整机挂起未验证；本子层尚未重新完成实体按键或断开电池/USB 的完全冷启动测试，有限重启和负载测试也不能替代长期稳定性验证。**镜像 `v0.1.0-20261114` 与刷机程序 `v0.2.0` 的 Release 文件未替换**，本次同步源码和原机结果。构建背景见 [BUILD.md](../BUILD.md) 与[压缩引导层](BOOT-COMPACT.md)。
