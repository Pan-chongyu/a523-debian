# 启动流程精简

[English](../BOOT-STARTUP.md) · [日本語](../ja/BOOT-STARTUP.md) · [Español](../es/BOOT-STARTUP.md)

原机两次正常重启，五个桌面进程全部创建的时间为内核启动后 **21.73 / 21.64 秒**，原顺序基线为 **25.48 秒**，提前 **3.75 / 3.84 秒**。这是进程创建时间，不是目视可操作时间或按电源键计时。原有星空猫引导保持不变，硬件计数为 **5.920 / 5.939 秒**；本轮改善的是后续 Linux 启动，未测得新的首次亮屏提速。

完整保留 256MiB 内存与电压检查，把它提前到根文件系统和 CPU 时钟准备完成之后，取消对通用基础服务的等待。关机处理器先注册，再进行 CPU 调压。HS200/100MHz 改在同次启动的内存、温控和 CPU 检查通过后启用，排在 GPU 与 LightDM 前面。去除重复的外层 GPU 检查和屏幕交接诊断中的全局文件系统同步，保留探测前的实时 GPU 检查及像素验证。蓝牙在 LightDM 启动后后台初始化，原指令与等待完整保留。

蓝牙仍需约 15 秒后台初始化。因此 `graphical.target` 提前不等于所有启动任务更早结束，`systemd-analyze` 的总时间也不能作为桌面可操作时间。[实测报告](../../reports/boot-startup-20261114.json)分别保存进程时间、单元顺序和整个启动任务完成时间。

两次最终启动均通过 CPU、2.5GiB 八线程内存、GPU 图形/计算、600帧视频硬解和两轮直接文件读写联合负载，CPU 1416/1800MHz、HS200 100MHz 保持。零失败服务及观测到的内存、MMC、IOMMU、显示错误。完整内存训练、镜像 CRC、源码哈希、温控和租约回退保留；自动检查确认向右横屏 1280×800 和触摸矩阵。最终版实体按键计时及目视/触摸确认仍待进行，有限测试不等于长期稳定性保证。

失败试验保留记录：HCI 即时返回虽然通过模拟 UART 和热重启服务测试，冷启动仍在 0x0c52 超时，最终恢复原蓝牙代码；提前 CPU 后曾触发关机驱动供电检查冲突，最终显式要求关机处理器先注册。早期草稿的组件哈希清单也已修正，最终两次启动没有这些失败。

本次公开研究源码和测量结果，**镜像 `v0.1.0-20261114` 与刷机工具 `v0.2.0` Release 文件未替换**。原机增量依赖精确源码哈希和资格记录，研究脚本依赖历史原机采集文件，不是可通刷升级包；公开镜像升级需另行构建及实机验证。未公开设备凭据和签名密钥。
