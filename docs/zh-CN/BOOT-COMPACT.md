# 内核载荷压缩与启动精简

[English](../BOOT-COMPACT.md) · [日本語](../ja/BOOT-COMPACT.md) · [Español](../es/BOOT-COMPACT.md)

原机两次正常重启通过。引导载荷读取与 CRC 校验由 **5.00 秒降至 2.22 / 2.22 秒**，新增解压、搬移、CRC 与缓存清理合计 **0.265 / 0.265 秒**。实际读取量从 **15,008,256 降至 6,682,112 字节**，减少约 55%；无损解压后的内核与原版逐字节一致。

五个桌面进程全部创建的时间为 Linux 启动后 **19.83 / 19.96 秒**，本层前为 **21.64 秒**。这是进程时间，不是目视可操作时间。进入 Linux 的 ARM64 跳转硬件计数为 **8.58 / 8.58 秒**。首次星空猫图片仍为 **5.912 / 5.916 秒**，本层没有提前首次图片；未重新进行实体电源键计时。硬件计数和内核相对时间分开记录，未将其拼成按键到桌面的总时间。

引导先将压缩输入搬到输出区域以外，使用带边界检查的 LZ4 解码器。解压阶段临时启用限定范围的 RAM 恒等映射和缓存，低地址外设仍为 Device 类型；完成后清理内核到 PoC，关闭 MMU/数据缓存并恢复原 EL2 控制与翻译寄存器，再交给 Linux。五个载荷的原 CRC、解压内核 CRC、16 个内存边界别名检查及完整 4GiB 新鲜训练全部保留。

内存盘保留完全相同的 ARM64 BusyBox 和 `/init`，保留 USB 串口、恢复与根文件系统身份校验；去掉重复 BusyBox、手册、示例和打包钩子。关闭强制 115200 波特率早期串口调试与 `ignore_loglevel`，保留 USB 串口/网络恢复和内核日志。签名 SRAM 引导器、星空猫像素、GPT 和旧后备槽未改；写入过程中先选择后备槽，逐字节回读并保存分层恢复。

两次均通过 CPU、2.5GiB 八线程内存、GPU 图形/计算、600 帧硬解及直接文件存储联合测试，零失败服务及观测到的内存/MMC/IOMMU/显示错误。CPU 常驻 performance，档位 1416/1800MHz；GPU 请求 600MHz，保留温控与故障上限；HS200 100MHz、2GiB zram 和关闭浏览器预加载保持。向右横屏与触摸矩阵自动检查通过；第二次启动后，用户也确认星空猫图片、横屏桌面与触摸正常。有限测试不等于长期稳定性保证。

无缓存解压候选耗时 5.136 秒，已撤销；安装最终缓存版本前，实际验证过恢复原始父层。完整结果、失败候选与 ARM64 正常/损坏数据仿真见[实测报告](../../reports/boot-compact-20261114.json)。仿真会模拟缓存与系统寄存器，缓存/MMU 的硬件效果由两次实机启动验证。

此次发布研究源码和测量结果，**镜像 `v0.1.0-20261114` 与刷机工具 `v0.2.0` Release 文件未替换**。不是通用刷机升级包；构建器依赖历史原机载荷、目录和精确校验资料，见 [BUILD.md](../BUILD.md)。未公开原机专用安装器、身份采集、凭据或签名密钥。可分发镜像仍需独立构建与实机验证。前置层见[启动调度](BOOT-STARTUP.md)和[首次图片优化](BOOT-SPLASH-SPEED.md)。
