# 起動ログと画面の連続引き継ぎ

[English](../BOOT-CONSOLE.md) · [简体中文](../zh-CN/BOOT-CONSOLE.md) · [Español](../es/BOOT-CONSOLE.md)

検証した元の端末では、SRAM の起動画面から Linux DRM へ表示を維持して引き継ぎます。星空猫の画像の後に **実際のカーネルログを表示し、右向き横画面の XFCE デスクトップへ移行**します。所有者はログ表示、カラーバーと途中の暗転の解消、正常なデスクトップとタッチを確認しました。

動作中の PWM、DSI、パネル電源と VO0・VO1・DE 電源ドメインを保持します。保存された起動記録、タイミング、描画アドレスと電源を検証し、ネイティブドライバーがパネルリセットや電源断なしで引き継ぎます。ログ画像を DMA32 バッファにコピーして通常描画へ切り替えます。コールド初期化の診断用カラーバーと四色バッファは除去し、有効な最初のフレームまで黒で隠します。

ARM64 レンダラーは `/dev/kmsg` の実際の記録を回転済みの予約バッファへ描画します。ネイティブモジュールが所有権を取得すると旧物理バッファへの書き込みを停止し、VT1 への出力を続けます。疑似進捗ではありません。最初の SRAM 画像は変更しておらず、ログは Linux ユーザー空間から読み出せる段階で始まります。電源キー直後のログ表示や初回点灯の短縮は主張しません。

2 回の通常起動で 422 / 424 件のカーネル記録と表示の引き継ぎを確認しました。2 回目のログ初回描画通知は Linux 起動後 **5.48 秒**、5 つのデスクトッププロセス作成完了は **20.69 秒**でした。電源キーからの時間や目視の表示完了時間ではありません。42.51 / 44.06 秒の CPU・2.5 GiB RAM・GPU 描画/計算・600 フレームのハードウェアデコード・直接ファイル I/O の同時試験と、5 回の実パネルスリープ復帰が成功しました。表示・MMC・IOMMU のエラーと失敗サービスはありません。[検証データ](../../reports/boot-console-20261114.json)。

CPU performance 1416/1800 MHz、温度と障害制限付き GPU 最低要求 600 MHz、HS200 100 MHz、zram 2 GiB を維持し、ブラウザーの事前読み込みは無効です。署名済みローダー、画像、圧縮ペイロード、GPT と復旧スロットの実読ハッシュは不変です。ログがバッファを書き換え、DE を停止しないため、この子レイヤーは履歴を改変せず独立した検証を使います。

正確なターゲットカーネルの準備済みソースとビルド設定で構築します。構築だけではインストールしません。

```sh
sh research/tools/build_boot_console.sh KERNEL_SOURCE KERNEL_BUILD OUTPUT_DIRECTORY
```

公開入口の実行で、2 モジュール、レンダラー、GPL カーネル由来の 8×16 フォントがインストール済み SHA-256 と一致しました。[ソース](../../research/firmware/screen-boot-console)と同階層の関連ファイルを参照してください。検証スクリプトには元端末の正確な親構成と保護されたインストーラーが必要で、汎用更新手順ではありません。秘密情報や端末識別スナップショットは含めません。
